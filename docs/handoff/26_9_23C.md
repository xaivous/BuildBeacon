## 1. What this is

A Valheim 1.0 mod (BepInEx + Jötunn 2.30.2, net48) adding the **Build Beacon** and four add-on pieces that link to it.

- **Beacon** (`xai_build_beacon`). Materials used inside its radius cost less. It has its own model with four alcoves,
  a panel (Trophies and Discounts tabs, the player's inventory beside it), readable rules files synced from the
  server, and refunds that honour what was actually paid. It holds **4 creature ("mob") trophies of its own**, fixed.
- **Boss trophy holders**: "Boss Trophy Pillar" (`xai_beacon_bossholder_pillar`) and "Boss Trophy Mount"
  (`xai_beacon_bossholder_wall`, walls only). Each hangs one boss trophy on a hook. A boss trophy on a linked holder
  makes its biome's materials **free** inside the radius; each boss counts once per beacon.
- **Trophy racks**: "Trophy Column" (`xai_beacon_mobrack_column`) and "Trophy Panel" (`xai_beacon_mobrack_wall`, a 2 m
  square wall panel that tiles). Four creature-trophy alcoves each; every alcove is its own use target. Each rack adds
  **four creature slots** to the beacon's network.
- **Linking.** Holders and racks are vanilla crafting-station extensions of the beacon: placed within `HolderRange`
  (30 m), joined by the yellow thread, linked to the closest beacon in range.
- **Level and radius.** Level = 1 + linked holders + linked racks (any mix), max 8. Radius = 30 m + 10 m per level
  above 1 (100 m at 8).
- **Creature discounts are levels.** A rule gives a material a whole-number level; a beacon adds up the levels of the
  trophies in its network (its own slots and every linked rack). A non-stackable trophy counts once per network (a
  second copy is refused anywhere in it); a trophy marked Stackable counts every copy. The level maps to a percentage
  through `LevelPercents` (25, 60, 80, 90, 95: multipliers 1.33x, 2.5x, 5x, 10x, 20x); level 5 is the top.
- **Rounding savings.** Costs round up per placement; the fraction overpaid is kept per player and per material
  (saved with the character) and takes one item off a later piece. A HUD buff says "-1 Wood" or "4 free" when it does.
  The build panel shows the full price struck through beside the discounted one.
- **Overlapping beacons** (`Stacking`): Max = the beacon whose level takes the most off; Sum = levels added (capped).
  A material is free if any covering beacon frees it.
- **Hugin** explains the beacon the first time a player places one (vanilla tutorial system).
- The radius ring (blue) shows only while the player holds a build tool (hammer, hoe, cultivator).

## 4. The loops (details in the skills)

- **Code**: edit → `bash .claude/skills/build-deploy/scripts/build-and-verify.sh` → user launches →
  `bash .claude/skills/valheim-debug/scripts/log-tail.sh`. A STALE deploy means Valheim holds the DLL. A background
  bash loop that waits for `valheim.exe` to exit and then runs the build script works; ask first, since the user may
  be batching changes before relaunching. Any `dotnet build` of the solution also deploys.
- **Unity**: `Unity_RunCommand` (game types by reflection or directly; `PrefabUtility`, `SerializedObject`) → rebuild
  the bundle (`.claude/skills/unity-bundle/references/rebuild-bundle.cs`) →
  `bash .claude/skills/unity-bundle/scripts/copy-bundle-and-build.sh`. New pieces were built by instantiating a
  holder prefab as the template, swapping the model, adding children, `SaveAsPrefabAsset`, labelling `buildbeacon`.
- **Blender**: patch the script in the repo, write it into the text block, `exec` under a `temp_override` on a VIEW_3D
  area with undo pushes; it exports its FBX. Snapshot for the user with `bpy.ops.render.opengl` + `save_render`.
- **Icons**: temporary scene (EEVEE, 512 px, transparent film, Standard view, orthographic camera from
  (0.55, -1, 0.45), sun 3.0 + fill 0.8, world 0.45), temporary colours (dark stone 0.13, light 0.42/0.40/0.37, iron
  0.20 metallic 0.9), render, restore, delete the scene; downscale to 128 px with Pillow via `uv`.
- **Balance**: edit `DefaultMobRules` → `uv run --no-project python tools/balance/gen_matrix.py` (prints "below
  target" lines) and `tools/balance/gen_defaults.py` → update the README examples if they changed. The matrix page is

  `tools/unitypy/prefab_tree.py`.
- **New pieces**: follow `docs/plans/mob-trophy-racks.md`: decisions → spec → Blender → Unity → code → in game, with

## 5. Gotchas that cost real time (all handled, all recurrable)

- **`WearNTear.m_noSupportWear = true` means "requires support".** Stone-material pieces on wood collapse silently;
  the wall mount and the Trophy Panel use Wood support.
- **One bad Harmony patch aborts `PatchAll`.** Check signatures with sigdump first.
- **Saved config values beat new defaults.** Use a new key (done for `RadiusAtLevel1`, `RadiusPerLevel`, `MaxLevel`,
  `BeaconMobSlots`) or edit the Dev profile's cfg by hand (done for `LevelPercents`).
- **Rules files are written only when missing.** To try new default rules in the Dev profile, edit its files or
  delete them so the next launch writes the defaults (the mob rules file was deleted for the rebalance).
- **Player takes the first Interactable/Hoverable found upward from the hovered collider** (`Player.Interact` and
  `Hud.UpdateCrosshair` use `GetComponentInParent`, confirmed in the IL). Add our component before
  `StationExtension`; per-alcove `RackSlot`s on child colliders win over the rack; body colliders stop short of the
  alcoves so the slot boxes are hit first.
- **The nocost cheat (`Player.m_noPlacementCost`, B with cheats on, which dev mode enables) only skips
  `HaveRequirements` on 1.0**; `ConsumeResources` still takes what the player carries. PlacePiece's `cheated` is that
  flag. The savings commit ignores it; `RefundPatches` still skips recording when cheated (dev-only refund quirk).
- **A dedicated server never loads pieces**; the ZDO owner is the only writer.
- **Vanilla wood walls snap on their centre plane**; wall pieces sink into wood walls when snapped (kept as is).
- **Vanilla hides zero-cost requirement rows** (re-shown by a postfix). **With no container open, Ctrl+click drops
  the stack** (our patch takes it over while the panel is open).
- **Jötunn UI**: buttons play two sounds per click (`BeaconUI.Quiet`); `CreateScrollView` gives its inner "Scroll
  View" a fixed size (`FollowWrapperHeight` stretches it so the list can be resized); vanilla's `UITooltip` does not
  show on the panel (the panel draws its own hover box).
- **Valheim's tonemapping turns bright pastel emission white**; keep emission saturated, intensity ≈ 2.
- **Copied vanilla materials carry keywords**; the plugin disables them; materials are dressed once while on Standard.
- **A piece prefab's first renderer is often a snow overlay or LOD**: use `prefab:<name>/<material>` tokens.
- **Bundle mesh data is Z-up**; the `model` child is rotated -90° about X; Blender -Y is Unity +Z (front); Unity
  position = (x, z, -y). FBX export is meshes only: empties (attach/snap) are recreated in the prefab.
- **Blender icon renders**: read a temporary copy's bounds in local space; its world matrix still holds the display
  offset until the depsgraph updates.
- **Shell heredocs collapse `\\`** (and `\n` inside Python strings); write scripts that contain backslashes with the
  Write tool, or build them from `chr(92)`.
- **HTML opened from disk without a charset** shows UTF-8 as mojibake ("Â·"); generated pages are written as ASCII.
- **Float costs**: `10 * (1 - 20/100f)` is 8.0000001; rounding allows `DiscountRules.Epsilon` (1e-4).
- **MCP**: `Unity_RunCommand` "Unity not detected" → `GetState`, retry. Blender text edits do not dirty the file; the
  user saves and commits `totem.blend`. The Blender viewport needs `area.tag_redraw()` after view changes.
- **Rider once reverted the csproj**; `build-and-verify.sh` checks the embedded bundle.
- **The `[diag]` Remove/Destroy warnings fire on every hammer removal**; expected.

## 6. Decisions made, don't relitigate without the user

- One DLL; helpers in `BuildBeacon/Util`. Server rules files are authoritative, synced via Jötunn admin-only config.
- Boss trophies live on holders; the beacon takes only creature trophies (legacy bosses in the beacon keep counting,
  can be removed, not added). Each boss counts once per beacon (`BossSlots` 8 still caps counting); the panel shows the
  boss count without a cap.
- Holders and racks are vanilla station extensions of the beacon's `CraftingStation`, linked within `HolderRange`
  (30 m, synced), closest beacon wins. Level = 1 + holders + racks, max 8; radius 30 m + 10 m per level.
- The beacon's own creature slots are fixed at 4 (`BeaconMobSlots`); bosses add none. Each rack adds 4 to the
  network. Duplicates of a non-stackable trophy are refused across the network and count once if they slip in;
  stackable trophies are exempt. Beacons over their own limit from older saves keep all their trophies counting (the
  user has not asked to change that).
- Creature discounts are levels (`Trophy | Material | Level`, plus `Trophy | Stackable`); no flat or percentage
  rules, no MinCost. `LevelPercents` 25, 60, 80, 90, 95. Stacking Max = the beacon whose level takes most off.
- The default rules follow the balance targets (construction woods and stones: 4 from common trophies, 5 with a rare
  one; other materials 2 from common, about 4 with rare; rare-only drops 2). A starting point; refine later.
- Rounding savings are per player and per material, saved with the character, committed on every placement (cheated
  or not). The HUD buff shows only when the savings take an item off ("-1 Wood" or "n free").
- The Trophies tab counts the beacon's own slots and the racks' apart; the summary line and hover show one merged
  count ("5/12"). Rack trophies are read-only in the panel.
- Discounts tab rows: savings bar, segmented level bar (red → blue for levels 1 to 5; unreachable levels grey from
  `MaxMobLevel`), trophies right-aligned in a fixed-width column; hover: level, percent, multiplier, and the
  contributing trophies (in-network full, others dimmed, bosses starred). Help text sits bottom left on the Close row.
- Ring blue (0.44, 0.7, 1), shown only while holding a build tool. Hugin explains the beacon once per character.
- Slot changes follow vanilla ownership (Container handshake for the panel, ItemStand RequestOwn for trophies);
  edits are ward-protected; discounts apply to everyone in the radius. Refund default `PaidCost`.
- Blender edits only through the generator scripts. New pieces go through the staged plan with gates.
- Commits only when the user says "commit"; descriptive messages; unrelated work in separate commits where the files
  allow (a combined commit that lists its parts when they would not compile apart).
- MCP servers are project-scoped and committed (`.mcp.json`).
