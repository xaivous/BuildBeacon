## 1. What this is

A Valheim 1.0 mod (BepInEx + Jötunn 2.30.2, net48) adding one build piece, the **Build Beacon**. Slot boss trophies
into it and their biome's materials become free to build with inside its radius; creature ("mob") trophies give
small discounts. Radius and mob slots grow with the number of boss trophies. It has its own model, a trophy panel,
readable rules files synced from server to clients, and refunds that honour what was actually paid.

Repository: `E:\ValheimModdingWorkspace\Xaivous_BuildBeacon`, branch `master`, nothing pushed anywhere. Solution
`BuildBeacon.sln`. The user tests in an r2modman profile named **Dev**; the build deploys there automatically.

## 4. The loops (details in the skills)

- **Code**: edit → `bash .claude/skills/build-deploy/scripts/build-and-verify.sh` → user launches → `bash .claude/skills/valheim-debug/scripts/log-tail.sh`.
  The script reports a STALE deploy when Valheim holds the DLL; that is the common failure, not a build error.
- **Unity**: change → `Unity_ManageAsset Import` (only for disk edits) → `Unity_RunCommand` with `.claude/skills/unity-bundle/references/rebuild-bundle.cs` → `bash .claude/skills/unity-bundle/scripts/copy-bundle-and-build.sh`.
- **Blender**: patch the script text in Blender (anchored string replacement), `exec` it under a `temp_override` on a VIEW_3D area with undo pushes around it, screenshot, export FBX over `BuildBeaconUnity/Assets/Beacon/xai_build_beacon.fbx` with `use_selection=True, apply_scale_options="FBX_SCALE_ALL", object_types={"MESH"}, bake_anim=False`, save, mirror script to repo, then the Unity loop.
- **Diagnose**: log first; if silent, console commands; if about game code, `tools/sigdump`; if about a vanilla
  prefab's children or components and the game is not running, `tools/unitypy/prefab_tree.py` (the bundle id comes
  from `StreamingAssets/SoftRef/manifest_extended`, search for `<prefab>.prefab`).

Healthy log signature: `Loading [BuildBeacon 0.1.0]`, `Loaded 8 boss trophies (59 free materials), 59 mob rules`,
one `Vanilla material for ...` and `Beacon material ...` line per material, `Beacon effects from "stone_wall_2x1"`,
`Beacon glow: "_enabled" from piece_groundtorch_mist (child), centered on the crystal`, no HarmonyX errors, no
`Falling back to a guard_stone clone`.

## 5. Gotchas that cost real time (all fixed, all recurrable)

- **`WearNTear.m_noSupportWear = true` means "requires support"** on 1.0. Stone-material piece on wood collapses on
  the first wear tick with no log line. Beacon has it and `m_supports` off. If a piece breaks silently, read
  `[diag]` lines in the log; do not guess at biome fields.
- **One bad Harmony patch aborts `PatchAll`**: every patch goes missing, not just the bad one. `PlacePiece` is void
  on 1.0; `ConsumeResources` is called from `UpdatePlacement`. Check signatures with sigdump before patching.
- **Rider reverted the csproj to HEAD once**, dropping the `EmbeddedResource` line; the build "succeeds" and the game
  says `AssetBundle buildbeacon not found in assembly manifest`. `build-and-verify.sh` checks the manifest. Commit
  early.
- **Valheim's tonemapping turns pastel or bright emission white.** Vanilla glows are Standard shader + `_EMISSION`,
  intensity ≈ 2, saturated colour. Emission lives in Unity materials; the plugin no longer overrides it.
- **Copied vanilla materials carry keywords** (`_VALUENOISEVERTEX_ON`, `_PARALLAXMAP`, `_TRIPLANARMAP_ON`);
  `CopyPropertiesFromMaterial` copies them. The plugin disables the vertex/parallax ones; floats alone are not enough.
- **A piece prefab's first renderer is often a snow overlay or LOD.** Use `prefab:<name>/<material>` tokens or
  `beacon_prefabs`/`beacon_tree` to pick the right material.
- **Bundle assets are persistent**: Unity refuses to parent under them; and Jötunn's `CreateClonedPrefab` refuses a
  name that already exists, hence the asset is `xai_build_beacon_prefab` and the piece is `xai_build_beacon`.
- **Unity project**: every DLL `.meta` in `Assets/Assemblies` has Auto Reference and Validate References off (global
  namespace collisions; Jötunn's unshipped YamlDotNet). New DLLs get fresh metas with both on. Consequence: Unity
  `RunCommand` code cannot see game types; read fields via `SerializedObject`.
- **MCP config**: `.mcp.json` must use `${VAR}` not `%VAR%`, no BOM, forward slashes; changes need a session
  restart, `/reload-plugins` does not reconnect servers. `Unity_RunCommand` sometimes says "Unity not detected":
  `GetState` then retry once. Blender edits: `undo` replaces mesh datablocks, re-fetch references after it.
- **Unity's `.mat` YAML re-derives `_EMISSION`** on import; turn emission off through `RunCommand`, not by editing
  the keyword list.
- **The wisp torch has no `Fireplace` on 1.0** (Piece, ZNetView, WearNTear, HoverText only). Its orb, point light,
  flare, sparks and hum sit under an always-on child named `_enabled`. Looking only at `Fireplace.m_enabledObject`
  silently fell through to `piece_groundtorch_blue`, a blue *flame*. All the torches live in bundle `c4210710`.

## 6. Decisions made, don't relitigate without the user

- One DLL, no separate Core plugin; the Core helpers live in `BuildBeacon/Util`.
- Boss trophies: one of each per beacon; unlimited only in the sense that mob slots grow with boss count.
- Server's rules files are authoritative; sync rides on Jötunn admin-only config entries, no custom RPC.
- Refund default `PaidCost`, recorded per piece on the ZDO.
- Materials: vanilla textures via templates, authored colour as tint; emissive parts on Standard as authored.
- Blender edits only through the generator script. Crown vocabulary: cap (pyramid), abacus (block), capital
  (flare), cornice ring, band, runes.
- Commits only when the user says "commit"; descriptive messages; split unrelated work into separate commits.
- MCP servers are project-scoped and committed (`.mcp.json`).
