## Stage A: make the repository safe to publish

### What the audit found clean

- **No game binaries, now or in history.** The Unity project's `Assets/Assemblies/*.dll` (assembly_valheim, the
  publicized game assemblies, PlayFab, Steamworks...) are ignored by `BuildBeaconUnity/.gitignore`; only their `.meta`
  stubs are tracked, and `git log --all` shows no `.dll`, `.zip` or game asset ever added.
- **No extracted game assets.** The asset bundle, FBXs and `totem.blend` are ours: the models are generated by our
  scripts, the icons are our Blender renders, `totem.blend` packs no images, fonts or libraries. Vanilla materials are
  borrowed at runtime (`MaterialTemplates`), never shipped.
- **No secrets.** No keys, tokens or passwords in tracked files or history (the only hits are Unity's empty
  `ps4NPTitleSecret`/`metroCertificatePassword` settings). `Environment.props` (local paths) is ignored.
- **Devlog screenshots** (`docs/devlog/media/`) show gameplay and editor panels only: no usernames, paths or IDs.
- **Game text** in `DEFAULT_DISCOUNTS.md` and the balance matrix is item and creature names only (factual use).

## Stage B: GitHub Pages site

**Status (2026-09-24): built, not yet deployed.** `site/` (template, CSS, `matrix.js`), `tools/site/build_site.py`,
`tools/balance/matrix_data.py` (the matrix data, split out of `gen_matrix.py`) and `.github/workflows/pages.yml`, as
described below; checked locally in both themes, at 1280 and 375 px, and against the generator's numbers. To go live:
Settings > Pages > Source "GitHub Actions" (Pages on a private repository needs a paid plan, so this follows going
public). Not done yet: the screenshots, the Thunderstore button (`THUNDERSTORE_URL`). Details in `docs/tools.md`.

### Hosting

- Publish with **GitHub Actions** (Settings > Pages > Source: GitHub Actions), not from `/docs`: `docs/` holds the
  internal notes and Jekyll would render them. Workflow `.github/workflows/pages.yml`: on push to `main` touching
  `site/`, `tools/balance/`, `BuildBeacon/BeaconConfig.cs` or `README.md`; set up Python; run the site build;
  `actions/upload-pages-artifact`; `actions/deploy-pages`.
- The build regenerates the matrix data from `BeaconConfig.cs` on every push, so the site never drifts from the
  defaults. `balance_matrix.html` stays as the maintainers' local page.
- URL `https://xaivous.github.io/BuildBeacon/` (once the repo is `xaivous/BuildBeacon`); set it as the repo's website, the manifest's
  `website_url`, and link it from the README.

### Structure

- Source in `site/`: `index.html` template, `site.css`, `matrix.js`; build script `tools/site/build_site.py` writes
  `site/_build/` (gitignored). Plain HTML/CSS/JS, no framework; the only runtime dependency is Google Fonts.
- **Aesthetic:** the matrix page's, extended to the whole site: Alegreya SC for display, Alegreya Sans for body,
  JetBrains Mono for numbers; its cool grey ground and surface, the blue accent, and the level colours red → orange →
  yellow → green → blue; light and dark themes from the same tokens (`prefers-color-scheme` plus a toggle). A header
  with the mod's name, version and download buttons (Thunderstore, GitHub releases).
- **Tabs at the top:** "The Mod" (default) and "Discount Matrix", as a `role="tablist"` with hash routes (`#matrix`)
  so each tab can be linked and the back button works.

### "The Mod" tab

- `README.md` rendered to HTML at build time (Python-Markdown with tables), so the site and the
  Thunderstore page say the same thing from one source.
- Plus: a few in-game screenshots (to take: the beacon lit at night with the ring, the panel's Trophies and Discounts
  tabs, a holder and the racks, the struck-through build prices) in `site/media/`, reused in the README by absolute
  URL so Thunderstore shows them too.

### "Discount Matrix" tab: a tool for players

- Split `gen_matrix.py` into data and view: the script exports `matrix.json` (trophies by biome with rare flags,
  boss rules, creature rules, level percents, the balance targets); `matrix.js` draws the table in the browser with the
  existing look (sticky headers, level-coloured cells, free cells, biome groups).
- Player features:
  1. **Filter** by biome, trophy or material (one search box), and hide empty rows and columns.
  2. **"My trophies"**: tick the trophies you have (or have slotted), and a results strip shows each material's summed
     level, percent off and multiplier, capped at the top level, the way the beacon adds them (non-stackable counted
     once). Remembered in `localStorage`.
  3. **Server rules:** paste the contents of your server's `BuildBeacon.BossRules.txt` and `BuildBeacon.MobRules.txt`
     (or pick the files) to see that server's matrix instead of the defaults. The parser follows `RulesFile`: `|`
     separated, `#` comments, `Trophy | Stackable` lines, names matched ignoring case, spaces and underscores.
  4. A "Balance view" toggle keeps today's targets and gaps rows for maintainers.
- Names only, no game icons: extracted trophy and item icons are the game's art and should not be redistributed.
- Checks: usable at 375 px wide (the table scrolls inside its box, the page does not), both themes, keyboard focus.

**Gate B:** the site builds in Actions, both tabs work on desktop and phone, the matrix matches `DEFAULT_DISCOUNTS.md`.
